# Requirements Checklist

Every item from `CRM_Advanced_PostgreSQL_Requirements.docx`, mapped to where it's implemented.

## §3 User Roles — ✅
`admin`, `manager`, `sales_agent`, `viewer` — `database/06_seed.sql` (roles table) · enforced in
`backend/src/middleware/auth.js` (`authorize`, `scopeSql`) on every route.

## §4 CRM Modules — ✅ all 14
Auth/Users, Teams, Leads, Customers, Contacts, Activities, Follow-ups, Tasks, Opportunities,
Products/Services, Quotes, Payments/Invoices, Reports, Audit Logs — one backend route file and one
frontend page each; see `backend/src/routes/` and `frontend/app/(dashboard)/`.

## §5–6 Schema & relationships — ✅
21 tables in `database/01_schema.sql`, matching (and extending) the suggested table list exactly.
1:N, N:N (`lead_tags`, `opportunity_products`) and self-referencing (`users.manager_id`)
relationships all present — see `docs/DATABASE.md`.

## §7 Constraints — ✅
PK (`GENERATED BY DEFAULT AS IDENTITY`), FK with explicit `ON DELETE`/`ON UPDATE` on every
relationship, UNIQUE (emails, `customer_code`, SKU, invoice/quote numbers), NOT NULL, CHECK
(amounts ≥ 0, probability 0–100, quantity > 0, enum-style status checks), composite UNIQUE
(`uq_contacts_customer_email`, `opportunity_products` PK, `uq_payments_invoice_reference`) — all in
`01_schema.sql`.

## §8 Advanced SQL — ✅ all items covered, see `database/07_practice_queries.sql` (35 queries)
INNER/LEFT/RIGHT/SELF JOIN (Q1–4) · multi-table joins (Q5) · GROUP BY/HAVING (Q6–7) · CASE (Q8–9) ·
subqueries/correlated subqueries (Q10–11) · CTEs (Q12–13) · recursive CTE (Q14, also
`get_user_hierarchy()`) · window functions ROW_NUMBER/RANK/DENSE_RANK/LAG/running total (Q15–18) ·
FILTER (Q20, also used live in `/reports/lead-conversion`) · DATE_TRUNC (Q21–23) · COALESCE (Q24) ·
EXISTS/NOT EXISTS (Q25–26) · UPSERT / `ON CONFLICT` (Q27–28, also live in the tags & opportunity
products endpoints) · RETURNING (Q29, used throughout the CRUD layer) · JSONB (Q30–31, also the
live `audit_logs` schema) · ARRAY (Q32–33) · full-text search (Q34–35, GIN indexes).

## §9 Views — ✅ 6 required, 7 delivered
`v_lead_pipeline`, `v_agent_performance`, `v_customer_summary`, `v_overdue_followups`,
`v_monthly_revenue`, `v_sales_funnel`, plus `v_lead_source_performance` — `database/04_views.sql`.

## §10 Functions/Procedures — ✅ 6 required, 9 delivered
`calculate_lead_score`, `get_customer_balance`, `convert_lead` (transactional),
`get_agent_monthly_stats`, `create_invoice_number`, `get_overdue_amount`, plus
`get_customer_financial_summary`, `get_user_hierarchy` (recursive), `recalc_invoice_status` and the
`mark_overdue_invoices()` procedure — `database/02_functions.sql`.

## §11 Triggers — ✅ 5 required, 9 delivered
Lead status audit, `updated_at` maintenance, generic audit log, payment validation, opportunity
total — plus invoice-total guard, invoice-status sync, opportunity stage→probability sync, and
lead-score refresh on new activity — `database/03_triggers.sql`.

## §12 Indexing & optimization — ✅
FK indexes, `leads(assigned_to, status_id, source_id, created_at)`,
`follow_ups(assigned_to, status, due_at)` (+ partial), `opportunities(owner_id, stage_id,
expected_close_date)`, unique indexes, partial indexes on active/open rows, GIN full-text indexes —
`database/05_indexes.sql`. **5 documented EXPLAIN ANALYZE before/after experiments** in
`docs/OPTIMIZATION.md` (requirement: at least 5).

## §13 Transactions & integrity — ✅
Lead conversion (`convert_lead`, PL/pgSQL, row-locked) · invoice + initial payment created in one
DB transaction (`POST /invoices` with `initial_payment`) · bulk lead import with per-row
`SAVEPOINT`s and a fully-atomic mode (`POST /leads/import`) · every write in the API runs inside
`BEGIN`/`COMMIT`/`ROLLBACK` (`backend/src/db.js` → `tx()`) · concurrent-payment test reproduced and
documented in `docs/DATABASE.md`.

## §18 PostgreSQL Practice Tasks (20 numbered tasks) — ✅ all 20, 1:1
`database/08_practice_tasks_18.sql` answers every numbered task literally (top 10 agents by
conversions, leads with no activity, customers with no follow-up in 30 days, agents above team
average conversion, MoM growth, cumulative revenue, agent ranking, latest activity per lead,
second-highest opportunity, duplicate emails keeping the newest, customers over a balance
threshold, best source per month, weighted sales funnel, recursive hierarchy, multi-step CTE
report, EXPLAIN ANALYZE reference to `docs/OPTIMIZATION.md`, source/tag UPSERT, transactional lead
conversion, the status-history trigger, and the financial-summary function).
